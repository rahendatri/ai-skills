# Explanation

# Input

Multiple discovery/research sources from a single product discovery project. Any combination of:
- Notion pages containing raw interview transcripts and/or a problem dump
- A competitive intelligence / product vision deck (pptx)
- A Miro board (e.g. a user journey map with sticky notes)
- Spreadsheets of quantitative data (xlsx/csv)

Before synthesizing, the following must be known — either stated by the user or found in a source:
- The project brief (problem area, sponsor, user population)
- The north star metric the team is trying to impact
- The full list of discovery sources to cross-reference

# Output

- A structured, numbered problem list (max 10–15 problems, or a limit the user specifies)
- For each problem: a one-sentence user-centric statement, its supporting source(s), and a confidence level (data-validated / qualitatively validated / cross-validated / single-source)
- Consistency notes: conflicts between sources, items intentionally excluded, and any source that was empty or inaccessible

# How it works

This skill cross-references discovery sources in the following steps:

1. Confirm the required context (brief, north star metric, source list) before touching any source — ask rather than guess
2. Read every source in full: raw interview transcripts over synthesis pages, quantitative data segmented around the north star metric, competitive decks for gaps and internal tensions, and Miro boards paginated to completion
3. Cross-reference findings across sources, writing one problem per root cause and grading each by source strength
4. Produce the final list, then handle follow-ups (new sources, scope exclusions, re-translation) as revisions to the same list rather than restarts
